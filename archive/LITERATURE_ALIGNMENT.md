# Best-practice and literature review

Checked against primary sources on 2026-10-13. This is a targeted review, not an exhaustive survey or a leaderboard. The implementation is a scoped CPU baseline with literature-informed evaluation. No evidence establishes state-of-the-art detection quality, adversarial robustness, or edge deployment performance.

## Findings across five themes

| Theme | Primary evidence | Alignment and gap |
|---|---|---|
| Layered detection and independent enforcement | [OWASP prompt-injection guidance](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) recommends layered controls, external authorization, limited privileges, and segregation of untrusted content. [CaMeL](https://arxiv.org/abs/2503.18813), March 2025, studies control/data-flow separation and capabilities. | Rules plus ML and independent tool authorization are appropriate. This scanner provides verdicts; it does not implement a capability system, sandbox, or authenticated action executor. App-supplied provenance now drives one narrow contextual rule. Broader source-aware routing and authorization remain deferred. |
| Adaptive adversaries | [Adaptive Attacks](https://arxiv.org/abs/2503.00061), February/March 2025, bypasses the evaluated defenses in its experimental setup. [AutoDojo](https://arxiv.org/abs/2606.15057), September 28, 2026 revision, studies adaptive success-feedback attacks and task specification. | Static paraphrases and decoy flooding alone cannot establish adaptive robustness. Task 3 now declares attacker query budgets/feedback and separates explicit tasks from open-ended delegation. This is future evaluation, not a completed robustness result. |
| Long documents and agent outcomes | [AgentDojo](https://arxiv.org/abs/2406.13352), 2024, evaluates tool-using workflows. [LongPIBench](https://arxiv.org/abs/2608.28411), August 2026, studies long-context injection across application scenarios. | Window-position/boundary tests and guarded/unguarded replay fit these concerns. The 512-token classifier views do not model arbitrary cross-window or multi-turn dependencies. Existing tokenizer tests establish offsets/tail retention, not long-document attack recall. |
| Model scope and multilingual safety | [TextDetox's card](https://huggingface.co/textdetox/bert-multilingual-toxicity-classifier) describes binary multilingual toxicity; [Prompt Guard's card](https://huggingface.co/meta-llama/Llama-Prompt-Guard-2-86M) targets explicit overrides. [Qwen3Guard-Gen-0.6B](https://huggingface.co/Qwen/Qwen3Guard-Gen-0.6B) provides broader moderation categories and three severity levels, with vendor-claimed multilingual support. | Current models are reasonable narrow baselines, not comprehensive safety judges. Qwen is a future comparator, not a demonstrated better edge choice. Compare shared labels, Hebrew/Arabic data, CPU memory, and latency; do not import its advertised benchmark ranking. |
| Detection, abstention, and utility | [Selective Classification](https://arxiv.org/abs/1705.08500), 2017, studies risk versus decision coverage. [Saito and Rehmsmeier](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0118432), 2015, analyzes precision–recall evaluation with imbalance. | All-attempt denominators, representative prevalence, paired comparisons, and separate abstention reporting are sensible. Token inspection coverage and decision coverage are different. Partial scans can reduce apparent FPR by avoiding decisions, so utility and review burden remain required. |

## Engineering judgment

- **Reasonable starting point:** Small-window sequence classifiers avoid generative guard reasoning loops and can run locally. Rules provide interpretable signals; fixed work/state limits and caching make computational trade-offs inspectable. These are design rationales, not comparative performance findings.
- **Retained limits:** Chunk-only classification omits broader conversation/task context. Secret blocking covers one configured synthetic literal. Native-language annotations and held-out efficacy measurements are still needed. Prompt Guard was not executed.
- **Runtime:** Local-only loading and disabled networking during validation establish offline execution. They do not constitute an egress sandbox. The cooperative deadline cannot cancel one inference call; RAM is not hard-enforced. No claim of real-time edge readiness is supported.
- **Privacy:** The cache retains token IDs and scores in memory. Token IDs can encode sensitive content; process-local storage and absence of persistent raw-text logs do not mean zero sensitive retention. A deployed implementation needs lifecycle/retention controls.
- **Defaults:** 512 tokens follow the classifier interfaces; overlap retains local boundary context at extra cost. Eight windows and a bounded LRU demonstrate work/state controls. The 30-second limit is a development guard, not a production latency target. Evaluation must select deployment budgets.

The assignment asks for a minimal POC and an evaluation proposal, not a new model or proof of SOTA. The appropriate next step is comparative measurement against real models and adaptive workflow attacks. Expanding the implementation before that evidence would make the submission larger without establishing better protection.

The revised execution baseline uses ungated [DeBERTa injection](https://huggingface.co/deepset/deberta-v3-base-injection), whose card lists English/German and warns about false positives. The saved joint run observes benign quotation/repetition blocks. Prompt Guard remains an unexecuted multilingual candidate; this substitution does not establish Hebrew/Arabic injection quality.
